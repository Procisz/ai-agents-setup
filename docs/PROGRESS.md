## How to resume

1. Read this file, then `docs/PLAN.md`.
2. Find the first step below that is not `done`.
3. If that step is a workflow run:
   - Same Claude Code session: check `/workflows`. A run that hit the usage limit waits and continues on its own (at most twice per run). If it failed or was stopped, resume it with `Workflow({scriptPath: <script>, resumeFromRunId: <run id>})`: finished agents replay from cache.
   - New session: runs cannot be resumed across sessions. Read the run's `journal.jsonl` (one line per finished agent, with its full result), check which files exist in the repo, then continue from the first unfinished stage with a new, smaller workflow or by hand.
4. Working mode (the user's standing instruction of 2026-10-08, PLAN 18 item 6): inside a milestone, start every next step without asking: builds, reviews, fixes, probe runs within the milestone plan's caps, and installs into `~/.claude` (always with a backup; report the diff and the backup set afterwards). Ask the user only at a milestone boundary. At every milestone boundary, commit all changes and push to origin, then ask what comes next. When a step needs something only the user can do (another machine, an interactive `wf` task, a GUI dialog), start a terminal process yourself if possible, otherwise ask for that specific help and continue with other steps meanwhile.
5. After finishing a step, update this file: the step status, the log, and "Last updated".
6. Before `node wf.mjs update` and at the start of each milestone, read the newest scheduled CI run (the weekly drift run of M5.4: claude-real and linux-fresh with the newest Claude Code, no Claude cost): `gh run list --workflow ci.yml --event schedule --limit 1`, then `gh run view <id>`; its job summaries name the Claude Code version and the check counts. A red run there is the first sign that a new Claude Code release broke the install. On GitHub Free a run does not start once the month's Actions minutes are used up (annotation: account payments failed or the spending limit needs raising, D96): such a run is no evidence either way, so rely on the local checks instead, after the update or at the milestone start (the full suite, `lint --self`, `doctor`, and `probe m1` when doctor says it is due).
