# Decisions from measurements and probes

This file records what was measured, when, and which decision it drove. `node wf.mjs probe <id | m1 | all>` appends a dated section after every live run, with one row per probe (home, status, key metrics, cost) and the notes of any probe that did not pass. The raw stream and evidence of each run stay in `probe-output/<stamp>.json`, which git ignores.

How to read the probe sections:

- `pass`: the probe's pass criteria from `docs/PLAN.md` section 15 held.
- `fail`: Claude Code ran, but a criterion did not hold. The notes name it. Decide whether to change a persona, a setting or the plan, and record that decision here.
- `error`: the probe could not complete (setup failed, no result event, budget cap reached, timeout). Rerun before drawing conclusions.
- `skipped`: not run, for example because the requested `--home` mode does not apply to that probe.

## 2026-09-28 manual measurements on this Mac (Claude Code 2.1.283)

Measured by hand with `claude -p` before the probe harness existed. The first-request size is input plus cache creation plus cache read tokens of the first API request, counted once per request.

| # | Measurement | Result |
|---|---|---|
| 1 | First request of a lean persona with three tools and `omitClaudeMd: true` | 3,675 tokens. A default subagent starts at about 50,000 |
| 2 | First request of a lean persona that loads the rules files (`omitClaudeMd: false`) | 3,222 tokens. It quoted `~/.claude/rules/house-rules.md` without any tool call, so the rules reach a persona through the normal context |
| 3 | The same kind of persona with `omitClaudeMd: true` | the rules files are dropped together with CLAUDE.md, not only CLAUDE.md |
| 4 | First request of a fresh CLI main session | about 48,600 tokens before the machine fixes, about 43,100 after them |

Decisions:

- D1 (from 1): per-persona startup is cheap when the tool list is narrow. Every persona lists only the tools it needs. Probe P1 gates the size after each upgrade: workers at most 15K, wf-scout and Explore at most 10K, hard limit 20K.
- D2 (from 2 and 3): the house rules live in one rules file, `rules/wf-house-rules.md`, instead of being compiled into every body. Writer personas and the verifier keep `omitClaudeMd` off, so they receive the rules and the project CLAUDE.md. Probe P3 re-checks both halves with canary tokens.
- D3 (from 3): Explore keeps `omitClaudeMd: true` and therefore does not see the rules. That is accepted for a read-only searcher whose output goes to the parent agent, which does see them.
- D4 (from 4): the expensive context is the main session, not the personas. The orchestrator stays lean, and its delegations point at files under `.work/` instead of pasting content.

## 2026-09-28 integration decisions (M1 build)

Taken while integrating the M1 modules, from the official Claude Code docs and a sandbox end to end run. Probes P8 and P9 confirm them live.

- D5: the Bash and PowerShell gate handlers use the `if` filters `Bash(*git*)` and `PowerShell(*git*)`, not `Bash(git *)`. Before matching, Claude Code strips only leading `VAR=value` assignments and its fixed wrappers (`timeout`, `time`, `nice`, `nohup`, `stdbuf`, `command`, `builtin`, `noglob`), so `git *` let `env A=1 git push`, `sudo git commit` and `/usr/bin/git commit` skip the gate. `*git*` starts node for every command that mentions git, and the gate's tokenizer decides. P8 step 1 covers the wrapped forms.
- D6: the stop hook resets a worker's contract retries, like its runner send-backs, on every fresh run (`stop_hook_active` false). A worker resumed with the user's answers therefore gets its two retries again. `maxResumesPerAgent` still bounds the total.
- D7: a verifier after a fix cycle reads the same files as the first one (task.json, diff.patch, checks.json) and never an earlier verifier's result, so every verification stays fresh and unanchored (PLAN sections 8 and 10).
- D8: the orchestrator trusts `checks.json` only when its `agent_id` is the coder's and its `resultSeq` equals the `seq` of the coder's newest result file. Timestamps have one-second precision and cannot order a result and its checks.

## 2026-09-29 Sonnet 5.5 intake (Claude Code 2.1.283 and 2.1.284)

Measured on this Mac on 2026-09-28 with Claude Code 2.1.283: one `claude -p --model claude-sonnet-5-5` call from a temporary directory, capped at $0.30.

Decisions:

- D9 (from 5 to 7): `registry.claude.minVersion` is 2.1.284. Below it doctor reports an error and install skips every persona file until `claude update` has run. Claude Code 2.1.284 was installed on this Mac on 2026-09-29. `claude.features` records the model floors (`model claude-sonnet-5-5` 2.1.284, `model claude-opus-5-5` 2.1.280), so doctor warns while Claude Desktop bundles an older Claude Code and names the personas it breaks. Desktop on this Mac bundles 2.1.280 and 2.1.281, so the wf personas are CLI-only until Desktop ships 2.1.284.
- D10 (from 5 and 6): probe P0 fails on any `unrecognized_model` notice and on a `modelUsage` context window that differs from the registry `window` of a persona model (1000000 for Sonnet 5.5, Sonnet 5 and Opus 5.5, 200000 for Haiku 4.5), so a Claude Code that does not know a persona model can never pass as a correct binding.
- D11: `claude-sonnet-5-5` replaces `claude-sonnet-5` for wf-coder (medium), wf-test-writer (medium), wf-test-writer-deep (high) and wf-docs (low), as PLAN section 18 item 4 decided. Probe P12 compares wf-coder on Sonnet 5 medium, Sonnet 5.5 medium and Sonnet 5.5 high on two fixtures, and its rule (PLAN section 15) says keep, revert or which effort to use. `claude-sonnet-5` stays in the registry as the safety fallback of Sonnet 5.5 (a cyber-flagged request re-runs on it, which P0, P9 and P12 record as a fallback, not a wrong binding) and as the probe driver model.
- D12: the 3,675 and 3,222 token figures above were taken on Haiku 4.5, and Sonnet 5 and Sonnet 5.5 count about 30% more tokens than Haiku 4.5 for the same text. P1 therefore records the model with every figure.
- D13: two prompt lines counter documented Sonnet 5.5 habits. The contract tells every worker to keep going until it can return done, needs_input or blocked, and never to stop only to ask whether to continue; wf-coder never creates test, documentation or helper files the task does not name. P8 counts tool names that differ only in letter case and checks that every Bash, Edit and Write call of the coder reaches the hooks under the exact name the gate matches.
